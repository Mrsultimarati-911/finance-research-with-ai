# 银行大模型客服应用与响应质量：写作模式案例

本例用同一组自制虚构材料展示六类请求：仅凭题目形成框架、局部修改、补写创新、只审查、按三章模板重构，以及审查预测设计。材料中的银行、团队、授权和研究方案均不对应真实机构或已完成研究；没有真实文献、日志权限或团队成果。

阅读[写作模式示例](写作模式示例.md)，可以对照请求范围与交付内容。局部修改只改变指定章节，范围外的无依据授权声明另列说明；全面重构时则可以根据请求撤除该声明。示例不伪造论文、DOI、数据或效果数值。

可复制请求：

```text
用 proposal-writing，围绕“银行大模型客服应用如何关联服务响应质量？”先给研究框架，不扩写初稿。区分披露与实际应用、响应速度与回答正确性，明确日志不可得时的公开资料路线。
```

```text
只修改给定原稿的“方法与数据”，其他章节逐字保留。范围外的问题列入修改说明，不把没有证明的团队授权写成已经确认。
```

```text
总问题保持不变，只补“创新与贡献”。目前没有真实文献和日志授权，不声称首次，说明贡献需要怎样核实，以及条件不足时如何收缩。
```

```text
只审查给定原稿，按“位置—问题—影响—建议”交付，不自动重写。
```

```text
把给定原稿重构为“研究问题—研究设计—实施条件”三章，撤除没有材料支持的日志和合作授权承诺，缺失条件标为待补。
```

```text
只审查给定预测设计的信息时间、样本划分、调参、退出样本和交易成本问题，不运行分析、不保证预测效果。
```
