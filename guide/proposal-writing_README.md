# proposal-writing 使用说明

面向金融研究和社科课题，将研究问题整理为框架、计划书或修改稿。支持中文和英文材料，默认输出中文 Markdown。

## 快速开始

安装后在 Codex 中使用 `$proposal-writing`，Claude Code 中使用 `/proposal-writing`，或明确说“使用 proposal-writing”。未安装时，可要求先读取 [SKILL.md](../skills/proposal-writing/SKILL.md)。安装见 [项目首页](../README.md#3-安装方式)。

```text
使用 proposal-writing，围绕人工智能应用与商业银行运营效率，先形成研究框架。
列出总问题、子问题、研究任务、理论机制、方法与数据条件的对应关系。
团队基础、数据权限和合作条件未知的地方标“待补”。
保存到 outputs/银行AI课题/研究框架.md。
```

[完整目录包](../downloads/proposal-writing.zip) 用于解压后复制目录；[根级上传包](../downloads/upload/proposal-writing.zip) 用于宿主导入。保留所有支持资料与许可证。

## 输入与工作模式

可以输入题目、研究问题、提纲、已有稿件、导师要求、文献资料或正式模板。正式指南与模板、用户材料和已确定约束优先。

| 模式 | 行为与成果 |
|---|---|
| 构思 | 只有题目时先形成框架，列明问题、任务、方法、数据和待补条件。 |
| 完整起草 | 明确要求完整初稿时，按材料直接形成计划书草案。 |
| 局部修改 | 只改指定章节，交付修改稿与简要说明，保留其余范围。 |
| 补写重构 | 补足缺节或重整论证，保留已经确认的研究约束。 |
| 审查 | 指出问题位置、影响与改进建议。 |

不强制先运行其他 Skill、创建整套状态文件、组织专家调度或评分。

## 默认结构

没有指定模板时使用十部分结构：

1. 选题背景与现实问题。
2. 国内外研究现状与学术问题。
3. 总体目标与研究思路。
4. 研究内容及子课题关系。
5. 理论机制与研究假设。
6. 方法、数据与可行性。
7. 创新与贡献。
8. 进度及预期成果。
9. 研究基础与分工。
10. 参考文献。

子课题数量随研究问题组织，不固定凑数。提供模板后按模板的标题、顺序和约束写作。

## 完整流程

先区分文献事实、用户事实、拟检验假设和综合论证；理清“问题—机制—变量—方法—数据—成果”的对应关系，再扩写章节。已有框架继续处理，局部任务无需从头起草。

金融实证关注识别假设和竞争解释；预测研究关注信息时点及数据泄漏；理论研究关注假设和适用边界。摘要未说明的变量和统计细节写为未知。必要时使用宿主公开检索补充文献，用户内部稿不自动用于外部查询。

不虚构团队成果、数据权限、合作条件或已获支持。未取得正式申报指南时，交付通用研究论证，说明它的使用条件。

## 输出成果

按任务交付 `研究框架.md`、`计划书初稿.md`、指定章节的修改稿或审查建议。用户指定目录优先；未指定时可保存到工作区 `outputs/<课题简称>/`。

检查每个重要文献事实的来源，研究假设是否写为待检验，方法是否有对应的数据条件，创新是否有论证依据，以及“待补”是否充分。修改任务另附改动理由。

## 常用请求

```text
使用 proposal-writing，只给这个题目形成研究框架，暂不扩写正文。
```

```text
使用 proposal-writing，按已有提纲直接起草完整中文初稿。数据权限未知处标待补，不虚构研究基础。
```

```text
使用 proposal-writing，只修改“理论机制与研究假设”，其余章节保留；交付修改稿与修改说明。
```

```text
使用 proposal-writing，为这份计划书补写“方法、数据与可行性”，结合实际可用数据提出条件方案。
```

```text
使用 proposal-writing，审查问题、变量、方法和数据是否对应，定位识别设计与竞争解释的薄弱处。
```

```text
使用 proposal-writing，严格使用我提供的模板标题和顺序，将现有材料重新组织成研究方案。
```

## 可选结构化检查

普通写作任务无需建立 JSON 台账。已有结构化问题、来源和任务记录时，可用标准库检查器检查显式引用与对应关系：

```powershell
python -B -X utf8 ./skills/proposal-writing/scripts/check_project.py ./project-contract.json
```

结果以 JSON 输出到终端，不改写输入。字段与最小要求见 [工具说明](../skills/proposal-writing/references/tools.md)。检查器核对显式结构，不能证明文献真实、识别成立或方案具有创新性。

## 已知限制与参考

缺失全文、数据权限或正式模板会限制论证深度，保留为“待补”或条件方案。来源访问可能受登录、付费或网络限制影响。稿件不承诺申报、发表或政策采纳结果。
